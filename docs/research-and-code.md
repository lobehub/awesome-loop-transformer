## From translation to shared Transformer blocks

- [Recurrent Stacking of Layers for Compact Neural Machine Translation Models](https://arxiv.org/abs/1807.05353) (2018) — Compares repeatedly applying one layer with stacking independently trained layers in machine translation, measuring translation quality against parameter count.
- [NICT’s Participation in WAT 2018: Approaches Using Multilingualism and Recurrently Stacked Layers](https://aclanthology.org/Y18-3003/) (2018) — The NICT workshop report documents a translation system that repeats a three-layer Transformer stack four times. It also describes the multilingual training setup.
- [Balancing Cost and Benefit with Tied-Multi Transformers](https://aclanthology.org/2020.ngt-1.3/) (2020) — Trains a translation model at multiple combinations of encoder and decoder depth so that either depth can be chosen at decoding time.
- [Subformer: Exploring Weight Sharing for Parameter Efficiency in Generative Transformers](https://arxiv.org/abs/2101.00234) (2021) — Tests which layers to share in generative Transformers on translation, summarization and language modeling. [Code](https://github.com/machelreid/subformer)
- [Lessons on Parameter Sharing across Layers in Transformers](https://arxiv.org/abs/2104.06022) (2021) — Compares sequential, cyclic and reversing assignments of shared parameter sets across layers. The translation experiments isolate a choice that a single shared block cannot expose. [Code](https://github.com/takase/share_layer_params)
- [Staircase Attention for Recurrent Processing of Sequences](https://arxiv.org/abs/2106.04279) (2021) — A staircase step brings new tokens into a recurrent computation. Its Ladder variant holds the input window in place and reapplies the same Transformer across depth.
- [The Neural Data Router: Adaptive Control Flow in Transformers Improves Systematic Generalization](https://arxiv.org/abs/2110.07732) (2021) — Adds a copy gate and geometric attention to route information across recurrent updates. Compositional lookup, arithmetic and ListOps probe generalization to greater depth. [Code](https://github.com/RobertCsordas/ndr)
- [Sparse Universal Transformer](https://arxiv.org/abs/2310.07096) (2023) — Combines sparse experts with learned halting in a Universal Transformer. Translation and formal-language experiments examine how much computation the model uses. [Code](https://github.com/shawntan/SUT)
- [CoTFormer: A Chain-of-Thought Driven Architecture with Budget-Adaptive Computation Cost at Inference](https://arxiv.org/abs/2310.10845) (2023) — Lets a token reuse the Transformer at different depths and attend to earlier token states during refinement. The experiments vary the available inference budget. [Code](https://github.com/epfml/cotformer)
- [Relaxed Recursive Transformers: Effective Parameter Sharing with Layer-wise LoRA](https://arxiv.org/abs/2410.20672) (2024) — Groups pretrained layers into a recurrent stack and adds low-rank updates specific to each depth, testing how much behavior survives weight sharing.

## Algorithms and length generalization

- [Looped Transformers as Programmable Computers](https://arxiv.org/abs/2301.13196) (2023) — Constructs the weights of a looped Transformer that executes instructions supplied in its input. The accompanying programs include a calculator and linear algebra routines. [Code](https://github.com/jysohn1108/Looped-Transformer)
- [Simulation of Graph Algorithms with Looped Transformers](https://arxiv.org/abs/2402.01107) (2024) — Constructs attention heads that access a graph and a loop body that implements algorithms including breadth-first search and Dijkstra’s shortest path. The repository contains the simulations. [Code](https://github.com/watcl-lab/graphalgosimulation)
- [AlgoFormer: An Efficient Transformer Framework with Algorithmic Structures](https://arxiv.org/abs/2402.13572) (2024) — Places a shared algorithmic loop between task-specific input and output transformations. The paper examines when this structure helps represent iterative algorithms.
- [Looped Transformers for Length Generalization](https://arxiv.org/abs/2409.15647) (2024) — Trains looped models on short instances of algorithmic tasks and evaluates on longer inputs, with the number of iterations allowed to grow. [Code](https://github.com/UW-Madison-Lee-Lab/looped-tf)
- [On Expressive Power of Looped Transformers: Theoretical Analysis and Enhancement via Timestep Encoding](https://arxiv.org/abs/2410.01405) (2024) — Studies how reusing weights constrains expressivity and what changes when the shared block receives an encoding of the current iteration. [Code](https://github.com/kevin671/tmlt)
- [Can Looped Transformers Learn to Implement Multi-step Gradient Descent for In-context Learning?](https://arxiv.org/abs/2410.08292) (2024) — Analyzes whether training can recover a multi-step optimization procedure in a restricted in-context linear regression setting. The assumptions and convergence analysis make this a counterpart to explicit weight constructions.
- [Reasoning with Latent Thoughts: On the Power of Looped Transformers](https://arxiv.org/abs/2502.17416) (2025) — Compares shared and untied models at matched executed depth on tasks including addition and multi-hop induction, then analyzes which tasks admit iterative solutions.
- [Thinking Deeper, Not Longer: Memory-Efficient Latent Chain-of-Thought with Depth-Recurrent Transformers for Compositional Generalization](https://arxiv.org/abs/2603.21676) (2026) — Tests a shared reasoning block on graph reachability, nested structures and less structured inputs. The comparison asks which kinds of task benefit from additional silent steps. [Code](https://github.com/hhchen1105/Depth-Recurrent-Transformer)
- [Beyond the Training Horizon: Mechanisms and Limits of Length Generalization in Looped Transformers](https://arxiv.org/abs/2609.33144) (2026) — Probes two recurrence-training schedules using state decoding and interventions. It traces how errors accumulate when learned computations run beyond their training horizon.

## Puzzles and recurrent state

- [Less is More: Recursive Reasoning with Tiny Networks](https://arxiv.org/abs/2510.04871) (2025) — Tiny Recursive Model refines a candidate answer alongside a latent state. The repository includes attention and MLP variants, making the attention configuration a small Transformer reference. [Code](https://github.com/SamsungSAILMontreal/TinyRecursiveModels)
- [Universal Reasoning Model](https://arxiv.org/abs/2512.14693) (2025) — Augments a Universal Transformer with short convolutions and truncated backpropagation. Its ARC experiments ablate the components of the recurrent solver. [Code](https://github.com/UbiquantAI/URM)
- [Are Your Reasoning Models Reasoning or Guessing? A Mechanistic Analysis of Hierarchical Reasoning Models](https://arxiv.org/abs/2601.10679) (2026) — Tracks HRM predictions across iterations on Sudoku. Cases with a single missing cell expose trajectories that settle on an incorrect answer. [Code](https://github.com/renrua52/hrm-mechanistic-analysis)
- [Universal Transformers Need Memory: Depth-State Trade-offs in Adaptive Recursive Reasoning](https://arxiv.org/abs/2604.21999) (2026) — Sweeps the number of memory tokens in an adaptive Universal Transformer on Sudoku-Extreme and measures how that choice changes both solution accuracy and halting depth. [Code](https://github.com/che-shr-cat/utm-jax)
- [Equilibrium Reasoners: Learning Attractors Enables Scalable Reasoning](https://arxiv.org/abs/2605.21488) (2026) — Studies whether repeated latent updates converge to valid puzzle solutions. The implementation includes an attention-based update, and the experiments vary both iteration count and the number of initial states. [Code](https://github.com/locuslab/EqR)
- [Fixed-Point Reasoners: Stable and Adaptive Deep Looped Transformers](https://arxiv.org/abs/2606.18206) (2026) — Uses convergence of the recurrent state as the stopping signal in a Transformer puzzle solver. Residual scaling and pre-normalization address signal propagation at large depths. [Code](https://github.com/nilskiKonjIzDunava/fprm)
- [Dense Supervision Is Not Enough: The Readout Blind Spot in Looped Language Models](https://arxiv.org/abs/2606.24898) (2026) — Shows how a normalized output head can hide growth in hidden-state magnitude even when every iteration receives a prediction loss. The repository includes diagnostics for reproducing this effect. [Code](https://github.com/Rituraj003/readout-blind-spot)

## Training across recurrent depth

- [Understanding Dynamic Compute Allocation in Recurrent Transformers](https://arxiv.org/abs/2602.08864) (2026) — Uses tasks with controllable token difficulty to evaluate adaptive depth. It measures separately where the model spends computation and how well it generalizes to larger instances. [Code](https://github.com/merlresearch/ANIRA)
- [Prioritize the Process, Not Just the Outcome: Rewarding Latent Thought Trajectories Improves Reasoning in Looped Language Models](https://arxiv.org/abs/2602.10520) (2026) — RLTT distributes credit across latent reasoning steps when tuning Ouro. The experiments compare this objective with GRPO under matched training and inference conditions. [Code](https://github.com/jonwill8/RLTT)
- [Simply Stabilizing the Loop via Fully Looped Transformer](https://arxiv.org/abs/2605.18797) (2026) — Routes the recurrent state to every layer through attention and tests whether this stabilizes training as the loop count increases. [Code](https://github.com/FuRuF-11/FullyLoopedTransformer)
- [Stabilizing Recurrent Dynamics for Test-Time Scalable Latent Reasoning in Looped Language Models](https://arxiv.org/abs/2605.26733) (2026) — STARS regularizes the local dynamics of the recurrent update. Arithmetic and math tasks test whether accuracy holds up when inference continues past the usual peak. [Code](https://github.com/njuyxw/STARS)
- [Bridging the Gap Between Latent and Explicit Reasoning with Looped Transformers](https://arxiv.org/abs/2606.31779) (2026) — LOTUS refines several latent positions in parallel and supervises them with tokens from worked reasoning traces. It compares accuracy and thought-generation latency with explicit chain of thought. [Code](https://github.com/yingfan-bot/lotus)
- [Loop Dropout: Regularizing Shared Updates in Looped Language Models](https://arxiv.org/abs/2609.34218) (2026) — Randomly drops applications of a shared low-rank adapter across iterations and rescales the surviving updates. An ablation tests what the rescaling contributes. [Code](https://github.com/NUS-HPC-AI-Lab/loop-dropout)
- [How Much Gradient Does Truncated Backprop Lose in Looped Transformers?](https://arxiv.org/abs/2610.28871) (2026) — Measures the portion of the weight gradient omitted at different backpropagation truncation depths in nine looped language models. [Code](https://github.com/Aur-Shalev-Merin/lost-gradient-looped-transformers)
- [Unlocking the Power of Loops in Pretrained LLMs with Loop Residuals](https://arxiv.org/abs/2611.31094) (2026) — LoopRes lets each layer attend to its outputs from a recent window of earlier iterations. The experiments test this modification while adapting pretrained language models. [Code](https://github.com/NUS-HPC-AI-Lab/LoopRes)

## Vision, speech and tabular data

- [Recurrent Vision Transformer for Solving Visual Reasoning Problems](https://arxiv.org/abs/2111.14576) (2021) — Combines a convolutional front end with a recurrent vision Transformer for same–different judgments. Ablations examine how feedback changes visual reasoning. [Code](https://github.com/mesnico/recurrent_vision_transformer_visual_reasoning)
- [LA-Sign: Looped Transformers with Geometry-aware Alignment for Skeleton-based Sign Language Recognition](https://arxiv.org/abs/2603.29057) (2026) — Applies a looped Transformer to sequences of skeletal joints for isolated sign recognition, with geometric alignment to help represent movement. [Code](https://github.com/mpuu00001/LA-Sign)
- [Déjà View: Looping Transformers for Multi-View 3D Reconstruction](https://arxiv.org/abs/2605.30215) (2026) — Reapplies a shared decoder block to per-view features in multi-view 3D reconstruction. The number of refinements can be changed after training. [Code](https://github.com/nv-tlabs/dvlt)
- [Test-Time Compute Scaling for ASR with Depth-Conditioned Looped Transformers](https://arxiv.org/abs/2606.04678) (2026) — LARM revisits speech encoder states between recognition checkpoints. Its LibriSpeech experiments track word error rate as inference depth increases. [Code](https://github.com/idiap/LARM)
- [LatentMT: Machine Translation with Latent Reasoning](https://arxiv.org/abs/2607.18618) (2026) — Adapts a looped language model for translation across 32 language directions. The authors report that quality gains concentrate in the early iterations. [Code](https://github.com/UBC-NLP/LatentMT)
- [LoopICL: Looping a single transformer block to solve tabular tasks](https://arxiv.org/abs/2609.36108) (2026) — A single shared block updates both cell and row representations for in-context prediction on tables. A learned gate can choose how many passes to run. [Code](https://github.com/amirbalef/loopicl)
- [Looped Diffusion Transformer](https://arxiv.org/abs/2609.40305) (2026) — Repeats Transformer blocks within each diffusion denoising step. This lets the experiments vary the denoiser’s internal refinement depth independently of the sampling schedule. [Code](https://github.com/OpenSenseNova/Looped-DiT)
- [AdaLoop: Thinking with the Vision Encoder](https://arxiv.org/abs/2610.21323) (2026) — Uses the question to guide repeated passes through a frozen vision encoder. The accompanying VisRO tasks probe which visual operations benefit from another pass. [Code](https://github.com/xrhan/AdaLoop)

## Inference, attention and memory

- [LT2: Linear-Time Looped Transformers](https://arxiv.org/abs/2605.20670) (2026) — LT2 tests linear, sparse and hybrid attention inside shared blocks. Recurrence can refine linear-attention memory or expand the receptive field of sparse attention. [Code](https://github.com/chili-lab/LT2)
- [Depth-adaptive Inference of Looped Language Models via Continuous Depth Batching](https://arxiv.org/abs/2608.09444) (2026) — Rebuilds batches between recurrent steps so tokens can exit at different depths. Its Ouro and Huginn benchmarks measure the throughput cost of scheduling that flexibility. [Code](https://github.com/kschwethelm/continuous-depth-batching)
- [LoopSpec: Pipelined Self-Speculative Decoding for Looped Transformers](https://arxiv.org/abs/2609.17184) (2026) — Uses early-loop predictions as drafts and overlaps drafting with deeper-loop verification. Includes a benchmark for self-speculative decoding. [Code](https://github.com/kaist-flexml-lab/loopspec)
- [WaveFront Decoding: Parallelized Self-Speculative Decoding for Looped Language Models](https://arxiv.org/abs/2609.23033) (2026) — Batches tokens at different positions and recurrence depths in the same block call so that drafting and verification advance together. [Code](https://github.com/summerbro-hhj/wavefront-decoding)
- [FlashLoop: Fast and Memory-Efficient Looped Transformers via Lazy Updates](https://arxiv.org/abs/2609.29812) (2026) — Reuses slowly changing token states and attention outputs, and compresses differences between successive KV caches. The experiments examine the cost of extra loops at long context lengths. [Code](https://github.com/Superone77/FlashLoop)
- [LoopQuant: Accurate and Efficient Post-Training Quantization for Looped Transformers](https://arxiv.org/abs/2610.16368) (2026) — Quantizes a looped model after training and allocates activation precision across passes according to sensitivity. The evaluation includes low-bit inference on Ouro. [Code](https://github.com/Kishon-zzx/LoopQuant)
- [LoopCache: Accelerating Long-Context Self-Speculative Decoding for Looped Transformers](https://arxiv.org/abs/2611.24301) (2026) — Studies self-speculative decoding at long context lengths, where batching different loop depths increases KV-cache traffic. It updates drafts as confidence changes across iterations. [Code](https://github.com/zZzZ9zZ9/LoopCache)
